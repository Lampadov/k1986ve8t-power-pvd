# К1986ВЕ8Т · детектор питания PVD

На отладочной плате с питанием **3,3 В** меняем порог детектора и смотрим на флаг `PVDP`. В опыте из статьи при повышении порога флаг сбрасывался на **3,6 В** вместо ожидаемых **3,4 В**. При снижении порога результат соответствовал ожидаемому. Напряжение питания при этом оставалось прежним.

В примере эту особенность учитывает `PVD_SetLevel()`. Сначала она записывает в `ULIMIT` код на ступень выше нужного, если код ещё можно увеличить. Следующей записью выставляет нужный порог. [Таблицы измерений и ход эксперимента][article].

## Собираем и запускаем из ОЗУ

1. Установите **Keil µVision** с **Arm Compiler 5.06 update 7**, пакет `Keil.MDR1986VE8T.0.5` и CMSIS Core 5.5.0 из ARM.CMSIS 5.8.0. В проекте устройство обозначено как `MDR32F8`. [Пакеты Миландр (Milandr)][packs].
2. Скачайте [`POWER_PVD_VE8.zip`][archive] и восстановите файлы устройства.

   ```console
   python tools/import_support.py POWER_PVD_VE8.zip
   ```

3. Откройте [PVD_Adaptive.uvprojx](PVD_Adaptive.uvprojx) и соберите **Target 1**. Образ размещается в ОЗУ по адресу `0x20006000`.
4. В **Options for Target → Debug** выберите отладчик, включите загрузку приложения при старте и укажите [Start.ini](Start.ini) в **Initialization File**. Этот сценарий берёт SP и PC из таблицы векторов образа, задаёт VTOR и запускает выполнение до `main()`.

## Что проверить в отладчике

В [main.c](main.c) программа перебирает коды порога в сторону уменьшения. Для каждого кода она проверяет `PVDP` **20 раз** и сохраняет первый устойчивый результат в `pvdLevelUccFall`. Эта переменная содержит код порога из регистра, в статье ему соответствует напряжение `Ulim`.

Затем программа включает прерывание PVD и в цикле программно меняет порог. При входе в `PVD_IF_Handler()` она восстанавливает порог из `pvdLevelUccFall`, гасит VD7 и сбрасывает флаг. Для проверки можно поставить точку останова в этом обработчике и добавить в окно просмотра `pvdLevelUccFall`, `PWR->ULIMIT` и `PWR->STAT`.

| Вариант | Какой код задаётся в основном цикле |
| --- | --- |
| `USE_PVD_HACK` включён по умолчанию | `pvdLevelUccFall + 1`, с предварительной записью большего кода |
| `USE_PVD_HACK` отключён | `pvdLevelUccFall + 2`, с запасом для наблюдаемого смещения |

Статью написал **Илья Лампадов**. В ней приведены значения `UCCMAX` для проверки порога в обе стороны и описана работа прерывания. [Статья и исходный архив][article].
